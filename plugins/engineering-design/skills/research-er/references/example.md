# 调研好坏对照

同一个主题（「技能分发目录选型」）的两个版本。
左边的问题在真实 AI 产出里最常见——对照着改。

## 坏例

```markdown
## 调研报告：技能分发目录选型

### 背景
在当今快速发展的 AI 编程领域，技能分发扮演着至关重要的角色。
为了更好地赋能插件库建设，我们对市面上主流的分发渠道进行了全方位、
深度的调研与剖析，现将结果沉淀如下。

### 分析
众所周知，Vercel 的 skills CLI 是一款非常优秀的工具，
它能够无缝集成多种主流 Agent，为开发者提供了强大的支持。
与此同时，其他方案也各有千秋，可谓八仙过海各显神通。
综上所述，我们需要综合考量多方面因素，做出最适合我们的选择。

### 总结
总而言之，本次调研让我们对技能分发有了更深刻的认识。
未来我们将持续关注该领域的最新动态，助力插件库更上一层楼。
```

**输在哪**：

1. 「当今快速发展」「至关重要」「全方位深度」——空话堆砌，删掉不影响任何信息；
2. 「众所周知」「非常优秀」「各有千秋」——零出处的评价，读者无法验证；
3. 「综合考量多方面因素」——等于什么都没说，结论缺失；
4. 整篇没有一行具体事实：没有数字、没有链接、没有对比维度。

## 好例

```markdown
> 调研日期：2026-08-23

## 背景
插件库需要决定技能资产按哪种布局组织，才能被最多安装器发现。
核心问题：skills/ 标准布局和 manifest 声明式布局，谁的覆盖面大？

## 发现

| 安装器 | 无 manifest 直扫 skills/ | 读 .claude-plugin/marketplace.json |
| --- | --- | --- |
| npx skills add | ✅ 固定位置扫描 | ✅ 追加发现声明的路径 |
| Claude Code 市场 | ❌ 不适用 | ✅ 必需 |

关键事实：skills CLI 的固定扫描清单不含 plugins/*/skills/ 这类嵌套布局，
manifest 里显式声明 skills 路径后才可被发现
（来源：vercel-labs/skills README「Skill Discovery」节）。

## 结论
事实结论：两种机制是叠加关系而非互斥。
倾向：仓库同时满足标准布局 + manifest 显式声明，双保险成本几乎为零——待 rfc 论证。
开放问题：Cursor 清单导出是否也要走同一条链路。

## 参考
- vercel-labs/skills README — https://github.com/vercel-labs/skills
```

**好在哪**：

1. 第一句就是问题，没有铺垫；
2. 每个论断带出处（表格数据 + 来源标注）;
3. 方案判断明确标了「倾向」，把拍板权留给 RFC；
4. 开放问题诚实列出，没有装作已解决。
