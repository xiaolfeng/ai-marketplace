## 问题
dist 产物入库与否悬而未决：每次全量 build 都污染 git status，
还出现过手改导出清单导致它与源清单不一致的事故。

## 方案
1. **`dist/cursor/` 作为交付物入库，随仓库分发。**
   它被外部工具直读，消费方无法自行重建——符合 research 0001 的交付物判定；
2. **导出清单只允许由 `npm run build` 生成。**
   手改 `dist/cursor/` 的 PR 一律不合并——两份手工索引必然漂移，
   本次事故正是这么来的；
3. **dist/ 其余路径一律 ignore。** 能从源码重建的产物不入库。

## 不做什么
- 不做发布时 CI 注入版本号——当前没有发版流水线，纯增复杂度；
- 不把产物迁到独立分支——多一处要同步的地方，事故面变大。

## 备选

| 方案 | 否决原因 |
| --- | --- |
| dist 全部入库 | 与源清单漂移正是本次要解决的问题 |
| dist 全部不入库 | 断供直读仓库的消费方 |
| CI 提交产物 | 引入机器人凭证与提交权限，收益撑不起风险 |

## 待定
Cursor 官方市场提交流程是否接受预生成清单——不阻塞本方案评审。
