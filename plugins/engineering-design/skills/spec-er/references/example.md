# 规范（spec）好坏对照

同一主题：「市场清单单一事实源规范」。规范的价值在于**可执行、可判责、可被单独引用**。

## 坏例

```markdown
## 规范：关于市场清单管理的若干规定

### 适用范围与背景

经过多轮深入讨论与充分调研，团队对清单管理形成了高度一致的认知，特制定本规范。

### 规范条款

1. 原则上采用 Claude 格式作为主要载体，同时尽量保持对其他平台的兼容性。
2. 大家在修改插件时要注意及时同步相关文件，确保数据一致性。

### 合规与后果

这一规范具有里程碑意义，将有力推动生态建设迈上新台阶。
```

**输在哪**：

1. **「原则上」「尽量」「要注意」**：规范里最致命的含糊词，Code Review 时根本无法据此判定对错；
2. **无法单独引用**：第 2 条「相关文件」指哪几个文件？用什么命令同步？全靠猜；
3. **没有正反例、没有校验门禁、没有否决项**：三个月后有人提议手改 `dist/` 应急时，没有条款拦得住。

## 好例

```markdown
# 市场清单单一事实源与构建同步规范

> 状态：adr · 日期：2026-08-25 · Scope：marketplace
> 承接：[插件标准全景调研](../research/0001-plugin-standards.md)

## 适用范围与背景

各客户端清单格式不通用，历史曾因人工漏改导致多端版本脱钩。本规范管辖仓库根清单、插件 manifest 及 `dist/` 导出目录；插件内部业务脚本不在本规范范围内。

## 规范条款

1. **`.claude-plugin/marketplace.json` 是唯一允许手写的市场清单。**
   严禁手工编辑 `dist/cursor/` 下的任何文件——导出物只能由 `npm run build` 从源清单生成。任何手改 `dist/` 的 PR 一律拒绝合并。
2. **插件版本变更必须三处同步。**
   修改插件发版时，必须在同一提交内同步更新 `plugins/<name>/.claude-plugin/plugin.json`、`.claude-plugin/marketplace.json` 对应条目与根 `README.md` 插件列表，并重跑 `npm run build` 提交最新的 `dist/cursor/`。
   - **豁免条件**：仅修改 `docs/` 或测试文件且不涉及插件内容与版本号时，无需递增版本。
3. **新增平台适配只扩导出脚本，不建第二份手写清单。**
   平台字段差异统一在 `scripts/` 导出器内做单向映射。

## 正反例与边界

- ✅ **合规**：改完 `plugins/bug` 后更新 `plugin.json` 与 `marketplace.json` 版本至 `0.0.2`，执行 `npm run build`，将源清单与 `dist/cursor/` 一并提交。
- ❌ **违规**：直接手改 `dist/cursor/.cursor-plugin/marketplace.json` 修补字段而不改源清单。
- ⚪ **合法边界**：本地调试时临时改动 `dist/` 观察格式，但提交前已用 `npm run build` 覆盖还原。

## 合规与后果

- **收益与代价**：改一处全平台生效，消灭多端索引漂移；代价是每次改源清单必须多跑一次 `npm run build`。
- **校验与暴露方式**：CI 与本地提交前执行 `npm run check`（内部调用 `build-cursor-manifest.mjs --check`），漂移时退出码为 `1` 直接阻断。
- **重评条件**：若未来所有目标客户端均原生支持直接读取 `.claude-plugin/marketplace.json`，则废止本规范第 1、3 条的导出要求。

## 否决项

- **多平台清单人工双写**：靠人记忆同步位置，第一次赶工就会漏——本规范立项正是因为发生过漏改事故；
- **CI 自动 commit 回写 `dist/`**：需向流水线授予仓库写权限并处理分支拉取冲突，安全与维护成本不成比例。

## 待确认

无（已于 2026-08-25 定稿冻结）。
```
