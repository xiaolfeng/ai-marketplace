> 状态：proposed · 承接 [0001](../rfc/0001-build-dist-commit.md)

## 背景
「哪些文件属于仓库交付物」在多次 PR 里反复争论，且已发生过一次手改产物导致
清单不一致的事故，需要把边界冻住。

## 决定
1. **`.claude-plugin/marketplace.json` 是唯一允许手写的清单。**
   禁止直接修改 `dist/` 下任何文件——导出物只能由脚本生成。
   手改产物的 PR 一律不合并；
2. **`dist/cursor/` 入库，dist/ 其余路径忽略。**
   前者是外部工具直读的交付物，后者可从源码确定性重建；
3. **修改插件后必须重跑 `npm run build` 并一并提交产物。**
   允许的例外仅限产物与源清单确实无关的纯文档改动。

## 后果
- 得到：改一处全平台生效；清单不一致类 bug 只可能出在导出器；
- 失去：每个插件 PR 多一步 build 提交，不能靠 CI 事后补产物；
- 违反时暴露方式：dist 清单与源清单字段对不上 → 说明有人绕过了导出器。

## 否决项
- **CI 发布时注入产物**：当前无发版流水线，为此引入机器人凭证不成比例；
  注意：未来建了发版流水线可重新评估，届时以新 ADR 取代本条；
- **双清单人工同步**：靠人记住两处版本号，第一次赶工就会漏——本 ADR 的动机正是这次漏改。
