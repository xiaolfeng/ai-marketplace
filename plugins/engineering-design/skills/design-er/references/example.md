# 设计稿好坏对照（覆盖 draft / rfc / adr 阶段）

同一主题：「从源清单导出 Cursor 清单」。对比重点是：**实施者能否直接定位修改位置、评审人能否看清取舍与边界、定稿后能否作为长期契约验收**。

## 坏例 1：空洞套话型（常见于劣质设计稿）

```markdown
## 工作方式

读取源清单后生成 Cursor 清单，并保证效率与兼容性。

## 数据与接口

清单格式保持一致，遇到问题给出友好提示。

## 验证

充分测试正常和异常情况。
```

**输在哪**：「格式保持一致」没有说哪些字段保留；「友好提示」没有失败条件；「充分测试」无法判定设计是否落地。照此实现仍需重新做一遍设计。

## 坏例 2：华而不实与汇报腔（常见于劣质 RFC/选型论证）

```markdown
## 目标与边界

在 AI 插件生态蓬勃发展的今天，我们独创了一套工业级清单导出引擎，一锤定音地解决了多平台兼容难题，保证绝对安全与零成本同步。

## 备选与取舍

- 使用第三方同步工具：开源工具全都笨重不堪、动辄崩溃，完全无法满足我们的极致需求。
```

**输在哪**：

1. 充斥「独创」「一锤定音」「绝对安全」等营销大词；
2. 违背**最强反驳原则（Steelman）**，靠贬低开源方案作稻草人来论证自研；
3. 缺少「不做什么」与「重新评估退出条件」。

---

## 好例（已收敛至 `rfc` / `adr` 质量的设计稿）

```markdown
# Cursor 市场清单导出与漂移检查设计

> 状态：rfc · 日期：2026-08-24 · Scope：build
> 承接：[构建产物与平台清单入库惯例调研](../research/0001-build-dist-conventions.md)

## 目标与边界

源清单变更后，`dist/cursor/` 随仓库交付且能在提交前自动检查是否过期。

- **本次范围**：`scripts/build-cursor-manifest.mjs` 的导出逻辑与 `--check` 漂移校验；
- **不做什么**：
  - 不做自建 registry API——当前插件规模无需独立服务端；
  - 不做发布时 CI 自动回写提交——避免引入机器人写权限与分支同步冲突。

| 现状类别   | 内容                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| 当前工作树 | 已有 `.claude-plugin/marketplace.json` 单一源清单                                 |
| 本次实现   | 新增零依赖导出脚本 `scripts/build-cursor-manifest.mjs` 与 `dist/cursor/` 产物校验 |

## 工作方式

1. `npm run build` 调用 `scripts/build-cursor-manifest.mjs`，读取 `.claude-plugin/marketplace.json`，经 `toCursorManifest` 过滤字段后写入 `dist/cursor/.cursor-plugin/marketplace.json`；
2. `npm run check` 以 `--check` 调用同一脚本，在内存计算期望 JSON 并与磁盘产物逐字节比对。

## 数据与接口

根级保留 `name`、`owner`，元数据从 `metadata` 或根级对应字段提取；插件条目仅透传 `PASSTHROUGH_FIELDS` 白名单字段。输出为 2 空格缩进 UTF-8 JSON，末尾带 `\n`。

## 异常与兼容

- 源清单缺失 `name`、`owner` 或 `plugins` 时抛出错误并以退出码 `1` 终止，不覆盖已有产物；
- `--check` 遇到产物缺失或字节不一致时退出码为 `1`，输出修复命令 `npm run build`；
- 物理边界：脚本仅校验字段结构与产物一致性，不校验插件内部 `SKILL.md` 语法（由 `claude plugin validate .` 负责）。

## 备选与取舍

| 备选方案                   | 否决原因                                                                 |
| -------------------------- | ------------------------------------------------------------------------ |
| 每平台手写维护独立清单     | 历史已发生漏改导致版本脱钩，人工双写必然漂移                             |
| JSON Schema 双向转换工具链 | 仅需从 Claude 向 Cursor 单向窄化透传，双向工具链的冲突合并复杂度远超收益 |

**重新评估条件**：若未来接入超过 3 个字段结构完全异构的目标平台且存在平台专有配置，再评估引入声明式多目标构建器替代单文件脚本。

## 验证

- 运行 `npm run build && npm run check`：退出码为 0；
- 修改源清单任意透传字段后不 build 直接运行 `npm run check`：退出码为 1；
- 删除 `dist/cursor/` 后运行 `npm run check`：提示产物缺失且退出码为 1。

## 待确认

无（评审确认后可直接将状态升为 `adr`）。
```
