# runbook-er · 手册模式（运行与排障 SOP）

公共约定：[../_shared/conventions.md](../_shared/conventions.md) ·
Scope 词表：[../_shared/scope-manage.md](../_shared/scope-manage.md) ·
流转与状态：[../_shared/lifecycle.md](../_shared/lifecycle.md) ·
语言纪律：[../_shared/writing-style.md](../_shared/writing-style.md)

## 模式定位：凌晨三点看着就能照做的操作指令

- **与 `design-er` / `plan-er` 的边界**：
  - `design` 讲系统原理与模块结构；
  - `plan` 讲某次改造或迁移的阶段推进与完结归档；
  - `runbook` 是**可重复执行的标准作业程序（SOP）**——当告警触发、校验报错或执行例行发布时，值班人员不看架构长文，直接按 `runbook` 的命令与判定表一步步操作止血并验证恢复。
- **状态机**：
  - **`draft`**：新建默认态，操作步骤与回滚命令尚待实测或演练确认；
  - **`active`**：经真实环境验证或演练通过、现行有效的手册；
  - **`deprecated` / `superseded`**：对应系统下线或被新手册替代。

## 操作流程

复制此清单并随做随勾：

```
手册进度：
- [ ] 1. 明确触发场景（哪条命令报错、哪个告警指标触发、或哪项例行发布操作）
- [ ] 2. 盘点前置检查项（权限、环境变量、依赖工具版本、只读状态确认）
- [ ] 3. 编写可直接复制执行的步骤与预期输出，补齐「止血与回滚」及「恢复验证」
- [ ] 4. 只扫 docs/engineering/runbook/ 取最大编号 +1，命名 NNNN-<scope>-<title>.md 落盘，初始状态 draft
- [ ] 5. 在 docs/README.md 的「手册模式（runbook）」分表登记，回报路径与待实测项
```

## 文档骨架

```markdown
# 标题

> 状态：draft | active | deprecated · 日期：YYYY-MM-DD · Scope：<scope>
> 承接：[关联设计/规范标题](../design/NNNN-scope-title.md)（如有）

## 触发条件与现象

什么情况下打开本手册：具体的报错信息、CI 门禁失败输出、告警指标阈值或例行操作时机。

## 前置检查

动手修改前必须确认的环境、权限、分支状态与工具可用性（每项给出检查命令与正常输出特征）。

## 执行步骤

按顺序列出操作步骤。每步包含：

1. **做什么**与具体命令；
2. **预期结果**（看到什么输出算成功，看到什么算异常需转入回滚）。

## 止血与回滚

当执行步骤中途失败或引发副作用时，如何在最短时间内撤销改动、恢复到操作前的安全状态。给出精确回退命令与禁止执行的危险动作。

## 恢复验证

操作或回滚完成后，依次运行哪些检查命令确认系统/仓库已完全恢复正常（必须包含退出码或可观测指标）。
```

## 手册纪律

1. **命令可复制，结果可判定**：禁止写「检查配置是否正确」「重启相关服务」这类空话——必须写出具体文件路径、命令参数和预期退出码；
2. **先止血后查因**：故障向手册把恢复服务/门禁绿灯放在最前，根因复盘交由事后 `replay` 插件处理；
3. **演练后才升 `active`**：新建默认 `draft`，由用户确认实测无误后再改为 `active`。
