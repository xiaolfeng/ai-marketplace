# 分支问答路径

这是构建个人 Agent 体系的访谈，不是在执行用户的业务任务。先提取当前对话已有答案，只问缺口；按回答进入下一层。不要一次把所有分支都丢给用户。每批最多四问，问题用自然语言，选项带简短说明。自由输入由问答工具提供，不手造“其他”选项。

## 入口

目标不明确时问“这次想搭建什么？”：

| 选项          | 说明                               |
| ------------- | ---------------------------------- |
| 创建 Agent    | 一名专门处理某类需求的个人角色     |
| 创建 Workflow | 多个角色按步骤交接、产出结果       |
| 管理模型      | 查看现有模型、筛选并记录用途映射   |
| 维护已有体系  | 调整个人角色、流程、模型或触发方式 |

默认全局生效，不重复追问“放哪个项目”。从实际宿主解析并展示将使用的用户级目录，遇到用户明确的自定义位置才补问。宿主无法确认时先解决宿主信息。

## Agent 分支

### 用途

问“这个角色主要帮忙做什么？”，根据用户描述提供 2–4 个贴近目标的候选职责和说明；如没有线索，可用“整理资料 / 写作表达 / 学习讲解 / 自定义助手”作为启发。这些只是问答选项，不自动成为最终职责。用户能用补充文本描述自己的用途。

接着确认典型输入和希望的结果。例如“整理资料”可能交付事实表、差异对照或要点笔记。把已确认的职责转成简短名字与 kebab-case ID，用户已有名字则沿用。

### 模型

先问“这个角色用哪种模型策略？”：

- **跟随当前会话（Recommended）**：派发时继承会话模型，以后切换会话模型也跟随。
- **固定一个模型**：从实际读取的模型目录中选择，以后保持该 provider/model。

选默认即结束选模，不追问 provider。选固定后再查真实目录、匹配用途并展示候选。若已有“快速整理”“深度推理”等 profile，展示其真实映射供复用；不要仅凭模型名声称质量或价格。用户要求“现在这个模型”时区分固定当前值与以后继续跟随会话。

候选选择例（尖括号代表实际读取值，不是可直接交付的候选）：

| 选项           | 描述                                         |
| -------------- | -------------------------------------------- |
| <模型显示名 A> | <provider A>/<完整模型 ID>，来自本次宿主目录 |
| <模型显示名 B> | <provider B>/<完整模型 ID>，来自本次宿主目录 |
| 继续筛选       | 按 provider 或关键词查看剩余 N 个候选        |

不需要“继续筛选”时省略。重名模型通过 provider 区分；同一模型在不同 provider 下是不同选项。零匹配时提供“刷新目录 / 调整筛选 / 跟随当前会话”。

### 触发与工具

问“希望在什么情况下用这个角色？”：

- **明确点名时用**：给出调用名称，description 保留用途，提示主要按点名使用。
- **匹配用途时用**：把具体场景和示例表达写进 description，允许宿主模型考虑派发。

补充问一个真实需求示例与一个不适用场景，已有答案则跳过。Agent 的触发是宿主选择行为；没有通用的“禁止自动派发”字段，不将“明确点名”描述为已强制执行。

问工具时按需求给“只读资料 / 可以编辑 / 需要运行命令”三个选项，解释 shell 会具备修改能力。只给职责所需工具，不能为了通用性默认全部开放。

## Workflow 分支

先问流程解决什么问题、接收什么材料、最终交付什么；然后分轮确认：

1. **成员**：复用已有角色、创建新角色、混合搭配。先列真实全局角色及其职责，不能只列插件自带角色。已有角色模型策略从文件读取；只有需要改变时才重新问。
2. **顺序**：谁先处理、谁接收哪些前序结果、最终由谁汇总。提供贴合用户目标的两三个步骤方案供选，步骤数跟着用途走，不强塞“开发→审查→测试”。
3. **每个新成员**：进入 Agent 子分支，独立确认用途、默认/固定模型、触发和工具。
4. **确认位置**：无需额外确认、最终结果确认、关键步骤确认。用户选择关键步骤后列出实际步骤供多选；确认位置与宿主原本的权限审批并存。
5. **流程触发**：显式命令或匹配具体需求，写清正例、反例和调用名称。
6. **异常**：说明默认停在失败步骤，检查产物后可重试；需要复杂恢复或并行时展示实际支持范围，不擅自承诺运行引擎。

交付可直接发现的独立 workflow 技能以及引用的原生角色，给出调用示例。搭建期间不会自行跑业务流程；用户明确要求试运行时才通过生成的入口测试。

## 模型管理分支

先区分“浏览/筛选 / 记录用途映射 / 更新映射”。读取宿主实际目录，按 provider、名称或关键词给候选。用户选择后再问这个 profile 用来干什么，建议用途名称并持久化。只浏览不写 profile；更新时列出依赖该 profile 的 Agent，说明需要重新生成才能生效。不要改模型提供商配置、凭据或当前会话模型。

## 维护分支

先读取 inventory 与已有定义，按用户目标给出“改职责与触发 / 改模型 / 改流程”入口。已创建内容不重新访谈一遍。用户手工修改或同名冲突时展示真实差异及保留方案，不要以重新初始化、删管理记录或改摘要来绕过保护。

## 交付概览

用简短列表列出名称、用途、触发示例、默认或固定模型、工具、全局路径与直接调用方法。答案齐备后生成，不追加“是否继续”。只在真实缺失决定或文件冲突时询问。
