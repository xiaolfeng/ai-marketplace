# Research Normal —— 常规调研

开放式调查执行器：围绕一个问题收集证据、横向对比候选、沉淀成一份
置信度透明的调研报告。本技能**只陈述不拍板**——选型决策属于 RFC 与 ADR 的领域，
报告的终点是把事实与权衡摆整齐，把决定权干净地还给用户。

与 [research-adversarial](../research-adversarial/SKILL.md) 的分工：
对抗模式靠辩论攻击既有认知，要求用户自带局部经验；本模式敞开收集，
零基础也可入场。一场完整示范见 [examples/scenario.md](examples/scenario.md)。

## 铁律

1. **范围先行。** 开查前确认三要素——回答什么问题、对比哪些候选、要什么形式的产出；缺哪项就显式声明假设后再开工。
2. **一手优先。** 取证按 官方文档 > 权威技术资料 > 社区口碑 的顺序；每条关键结论必须挂着出处与日期。
3. **多源交叉。** 核心结论至少两个独立来源印证；只有单一来源的如实标注，不许把它写成定论。
4. **时效敏感。** 引用必须带发布时间与版本号；用三年前的基准测试支撑今天的结论等于造假。
5. **只述不做。** 建议一律写成「考虑点」形式，禁止出现「应该选用 X」式的最终裁决句。

## 执行步骤

### 1. 立项：补齐三要素

用户的原始请求常常只有一个词（「调研下 Redis 替代品」），直接开查会把力气花错地方。
先把三问摆上台面：

| 要素 | 要回答的 |
| --- | --- |
| 问题 | 这次调研到底要回答什么具体问题 |
| 候选 | 有无指定对比对象？没有就先粗筛一圈，收窄后再和用户圈定 |
| 产出 | 简答 / 对比表 / 深度报告 |

用户明确表示不想被追问时，跳过提问，但要在报告开头声明所采用的假设范围。

### 2. 维度拆解

按问题性质从默认五维中裁剪，允许用户增删：

```
功能匹配 · 性能与规模 · 运维成本 · 社区与生态 · 团队迁移成本
```

纯概念梳理类请求没有「候选」概念，此步退化为知识框架搭建（分几个部分讲、每部分讲什么）。

### 3. 证据收集

检索顺序固定为四层：

1. 官方文档与 Release Notes —— 版本行为、能力边界的唯一权威；
2. 权威工程博客与技术会议分享 —— 生产环境的真实代价；
3. 仓库 Issue / PR / 讨论区 —— 已知缺陷与修复节奏；
4. 社区口碑（论坛、社交媒体）—— 只当线索，不当论据。

来源可信度的判定细则与 SEO 内容农场的识别要点见
[references/source-evaluation.md](references/source-evaluation.md)。
收集时同步建「已排除」清单：查过但不采用的来源记一行排除原因，防止后续重复踩坑。

### 4. 对比分析

多候选场景用统一矩阵呈现，列即候选、行即维度：

```markdown
| 维度 | 候选 A | 候选 B |
| --- | --- | --- |
| 功能匹配 | …（出处①） | …（出处②） |
```

两条纪律：

- **冲突不抹平**：来源互相矛盾时，两侧结论并列呈现并注明差异归因（版本不同 / 场景不同 / 测法不同），对应条目标「存疑」；
- **自述不算背书**：「官方宣称的性能提升」与「第三方实测数据」在矩阵里是两种东西，前者永远带「宣称」字样。

### 5. 报告交付

固定结构：

```markdown
## 结论速览        ← 三句话内正面回答立项问题，每个结论带置信度
## 分维度发现      ← 按 §2 的维度组织，逐条挂出处
## 对比矩阵        ← 多候选时的主表格
## 证据索引        ← 编号 · 来源 · 发布日期 · 版本
## 局限与开放问题  ← 没查到的、不敢确定的、需要实测验证的
```

置信度三级标注：**确定**（多源一致的一手信息）/ **倾向**（多源二手或单源权威）/
**存疑**(单源自述或来源冲突)。无内容可写的维度直接写「未获得可靠信息」，
禁止为了填满篇幅注水。

## 特殊情况速查

| 信号 | 处置 | 条目 |
| --- | --- | --- |
| 用户说「别问了直接给答案」 | 跳过确认环节，报告开头声明假设范围 | E1 |
| 关键问题查不到权威来源 | 降级采用社区口碑并全部标「存疑」，禁止包装成定论 | E2 |
| 两个权威来源结论相左 | 并列呈现 + 差异归因，相关结论整体降为「存疑」 | E3 |
| 候选过多无法逐一深查 | 先做一轮浅层粗筛收窄到 2~3 个，收窄理由写进报告 | E4 |
| 用户实际想要的是拍板 | 给完事实后明示「决策属 RFC 范畴」，指路 engineering-design | E5 |

## 自检

- [ ] 开查前三要素齐全，或假设范围已在报告中声明
- [ ] 每条关键结论都有出处与日期
- [ ] 核心结论经过至少两个独立来源交叉印证
- [ ] 单源信息与冲突信息均如实标注，没有被悄悄抹平
- [ ] 「宣称作」与「实测作」严格区分
- [ ] 报告包含局限与开放问题，没有装作全知
- [ ] 全文没有替用户拍板的最终裁决句
