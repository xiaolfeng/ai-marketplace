# need-merge · 分支合并

把源分支合并入目标分支。这是有副作用的本地分支操作：
安全手册中任何一条「必须确认」命中时，停下来用多选题向用户核实后再继续，
不得跳过检查直接合并。

安全手册（前置检查、方向一致性检测、冲突处置均以它为准）：
[../_shared/branch-safety.md](../_shared/branch-safety.md)

## 参数解析

从用户的话里提取两个分支，解析规则：

| 用户说 | 源分支 | 目标分支 |
| --- | --- | --- |
| 「把 feature/x 合并到 main」「merge feat into main」 | `feature/x` | `main` |
| 「把 feature/x 合并进来」（只提一个分支） | `feature/x` | 当前分支 |

一个分支名都没提时不要猜：用 `git branch` 列出本地分支让用户指定源与目标后再继续。

拿到的候选分支必须先过安全手册 C1 存在性检查；用户给的分支名不存在时，
列出最接近的现有分支供确认，而不是直接报错结束。

## 执行流程

1. 按安全手册 C1~C4 完成前置检查（分支存在 → 源≠目标 → 工作区干净 → 无进行中操作）；
2. 按安全手册采集 `A = git log --oneline <dst>..<src>` 与 `B = git log --oneline <src>..<dst>`，
   做方向一致性检测；A 为空、A 异常多、源为主干分支、分支名高度相似等情形必须先确认方向；
3. `git switch <目标>` 后执行 `git merge <源>`——不附加任何策略参数，
   fast-forward 属正常结果；
4. 出现冲突按安全手册「冲突处置」执行：列出冲突清单后停止，不自动解决；
5. 绝不 push；不做历史改写；不动提交信息；
6. 按安全手册「回报格式」返回结果。
