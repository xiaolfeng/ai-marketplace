# Scope 管理：业务域词表（提交侧）

git-commit 技能专用。本文与 engineering-design 的同名文件共用同一套定义：
**Scope 就是业务域**——从项目业务里分析出的一类业务环境，
如养成系软件的 用户(user)、树洞(treehole)。它回答「这次变更落在哪个业务域」。
提交类型（feat / fix 等公共公约）不在本文范围，速查见 SKILL.md。

## 词表与三种名字

唯一权威登记处是项目根的 `docs/scope-manage.md`（下称「台账」）。
每个 Scope 必须同时登记三个名字：

| 名字列 | 约束 | 谁在用 |
| --- | --- | --- |
| 2 字中文 | 固定 2 个汉字 | Git 可选模式 |
| 4 字中文 | 固定 4 个汉字 | Git 可选模式 |
| 英文单词 | 小写单个词 | 工程文档命名 + Git 可选模式 |

三列必须一次填齐——即使当前模式只用其中一列也照填，
避免未来扩展或切换模式时出现同义异名。

## 采用模式（一次性决议）

整个项目只用一种提交写法，首次决议后永久沿用：

- 触发条件：本次提交需要写 Scope，但台账不存在或未记录采用模式；
- 向用户提供三选一（推荐 2 字中文）：2 字中文 / 4 字中文 / 英文单词；
- 决议写入台账「采用模式」栏，之后所有提交照此取用，不再重复询问。

```text
选 2 字中文  →  feat(用户): 新增签到接口
选 4 字中文  →  feat(用户模块): 新增签到接口
选 英文单词  →  feat(user): 新增签到接口
```

## 选型引导

优先级：**功能模块 > 技术层级 > 子系统 > 省略**

| 层级 | 说明 | 示例 |
| --- | --- | --- |
| 功能模块 | 用户可感知的业务单元 | 用户、树洞、财务、认证 |
| 技术层级 | 横切多模块的技术分层 | 接口、数据库、中间件、配置 |
| 子系统 | 外部集成的独立系统 | mcp、dify、swagger |
| （省略） | 多模块/全局性变更 | 不写括号 |

## 新建 Scope 流程

1. **先查重**：查台账词表 + `git log --oneline -50`，任一名字列语义命中
   即视为同一 Scope，直接复用；
2. **起三名**：确属新业务域时，同时起 2 字中文 / 4 字中文 / 英文单词，
   请用户确认；
3. **登记**：确认后作为新行写入台账，之后两处都从表中取名。

## 防同义词纪律

1. 同一业务域全仓库只允许一个 Scope；「用户」与「user」并存即是事故，
   台账三列的存在正是为了让不同叫法挂到同一行；
2. 废弃的 Scope 在台账标注「废弃原因 + 归并去向」，历史提交不改写；
3. 台账缺失或未记录采用模式时按上文决议流程补齐后再提交，
   不得凭记忆自造 Scope。

## 边界判例

| 情形 | 正确动作 |
| --- | --- |
| 一个提交横跨两个功能模块 | 默认省略 scope；用户要求拆分则拆成两个提交各自带 scope |
| 词表里找不到贴切业务域且变更偏技术面 | 用技术层级或子系统行；同样走新建流程登记 |
| 写法与仓库历史不一致 | 以台账为准；台账与历史冲突时以历史为准并回修台账 |
