# 提交信息示例库：好/坏对照

SKILL.md 步骤 3 / 4 的配套示例。✅ 为可直接照抄的风格基准，❌ 为打回重写的典型事故。

## 标题行对照

### feat

```
✅ feat(用户): 添加 AI 语气预设管理接口
❌ feat: 更新代码                ← 空泛动词 + 缺 scope + 看不出改了什么
```

```
✅ feat(treehole): 实现匿名发帖冷却限制      ← 英文模式（采用模式决议后统一）
❌ feat(树洞模块): 新增了发帖冷却的功能啊    ← 口语尾缀 + 描述冗长 + 加了"了"
```

### fix

```
✅ fix(树洞): 解决会话创建时空指针异常
❌ fix: 修复缺陷                 ← 同义反复，等于没写
```

```
✅ fix(接口): 处理分页参数越界导致的 500 错误
❌ fix(接口): 修复bug            ← 中英混杂（中文项目）+ 空泛
```

### refactor

```
✅ refactor(认证): 抽取令牌校验公共逻辑     ← 行为不变，但说清动了哪块结构
❌ refactor(认证): 重构代码                 ← 行为不变也不许空泛
```

### perf / test / style

```
✅ perf(树洞): 改用游标分页降低列表查询耗时
✅ test(用户): 补充登录接口边界用例
✅ style(接口): 统一错误响应字段命名
```

### docs / build / ci / chore（全局变更省略 scope）

```
✅ docs(readme): 补充安装前置条件说明
✅ chore: 升级 eslint 至 9.x 并迁移扁平配置
✅ ci: 拆分测试与构建两条流水线
```

### revert

```
✅ revert: 回滚 "feat(认证): 添加 OAuth2 集成"
此操作回滚提交 abc1234，原因: 生产环境兼容性问题
```

## 正文示例

正文不是必选项——只在需要解释**为什么**、涉及架构取舍、或修复难以复现的问题时添加。

**例 1 · 解释难复现缺陷的根因：**

```
fix(树洞): 解决会话创建时空指针异常

原因: 并发场景下匿名身份初始化晚于会话落库，
内容: 将身份构造提前至事务内，并补充存在性断言
影响: 会话创建路径行为不变，仅消除竞态窗口
```

**例 2 · 记录架构取舍：**

```
refactor(认证): 抽取令牌校验公共逻辑

原因: 三处各自实现的校验已出现口径不一致，
内容: 收敛为单一中间件，废弃两份重复工具函数
影响: 登录与刷新接口响应体新增 debug 字段
```

**例 3 · 关联议题与 Breaking Change：**

```
feat!: 移除对旧版 API 的支持

原因: v1 协议已过维护期，双轨维护成本过高
内容: 删除 /v1 路由与兼容层
影响: 未迁移客户端将收到 404

BREAKING CHANGE: 认证方式从 Session 切换为 JWT
关闭 #123
```

## 反例合集（出现即打回）

| 反例 | 为什么不行 |
| --- | --- |
| `Co-Authored-By: ...` 出现在提交信息 | 违反铁律 2，作者就是用户本人 |
| 中文项目里写 `feat(auth): add login api` | 违反铁律 3（项目历史明确用英文除外） |
| 标题超过 50 字符 | 违反标题行规则，`git log --oneline` 会被截断 |
| "更新代码"、"修改一些问题" | 空泛词汇，看不出任何变更本质 |
| 一个 commit 同时混入功能与无关格式化 | 用户要求拆分时必须分组提交（铁律 4） |
| 正文每行超过 72 字符 | 违反正文模板约束 |
