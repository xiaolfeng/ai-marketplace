# need-rebase · 分支变基

把源分支变基到目标分支之上。这是有副作用且**改写源分支历史**的本地分支操作：
安全手册中任何一条「必须确认」命中时，停下来用多选题向用户核实后再继续，
不得跳过检查直接变基。

安全手册（前置检查、方向一致性检测、历史改写警告、冲突处置均以它为准）：
[../_shared/branch-safety.md](../_shared/branch-safety.md)

## 参数解析

从用户的话里提取两个分支，解析规则：

| 用户说 | 源分支（被重放） | 目标分支（新基座） |
| --- | --- | --- |
| 「把 feature/x 变基到 main」「rebase feat onto main」 | `feature/x` | `main` |
| 「把 feature/x 变基一下」（只提一个分支） | `feature/x` | 当前分支 |

一个分支名都没提时不要猜：用 `git branch` 列出本地分支让用户指定源与目标后再继续。

方向语义与 merge 相反，务必分清：merge 是「源的改动进目标」，rebase 是
「源被搬到目标之上、最后停在源分支」。拿不准用户想让谁站在谁上面时，
先回显两个分支名和各自最近提交让用户确认，再动手。

拿到的候选分支必须先过安全手册 C1 存在性检查；用户给的分支名不存在时，
列出最接近的现有分支供确认，而不是直接报错结束。

## 执行流程

1. 按安全手册 C1~C4 完成前置检查（分支存在 → 源≠目标 → 工作区干净 → 无进行中操作）；
2. 按安全手册采集 `A = git log --oneline <dst>..<src>` 与 `B = git log --oneline <src>..<dst>`，
   做方向一致性检测；A 为空（源已包含目标，无需变基）、A 异常多等情形必须先确认；
3. 执行安全手册「历史改写警告」：源分支已有上游且将造成本地与远程分叉时，
   必须先告知 force-with-lease 后果并取得用户同意；
4. `git switch <源>` 后执行 `git rebase <目标>`——不附加任何交互或策略参数；
5. 出现冲突按安全手册「冲突处置」执行：列出冲突清单后停止；
   需要放弃时仅在用户同意后 `git rebase --abort` 还原现场；
6. 绝不 push；完成后按安全手册「回报格式」返回结果，
   源分支已推送的场景追加远程分叉提醒。
