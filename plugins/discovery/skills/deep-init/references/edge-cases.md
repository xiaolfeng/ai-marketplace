# Deep Init 边界情况处置手册

遇到下列信号时，先读对应条目再行动：

| 信号 | 条目 |
| --- | --- |
| 目标不是 git 仓库 | E1 |
| 存量 AGENTS.md 无同步标记 | E2（配合问询协议 Q2） |
| 标记哈希不在当前分支历史 | E3 |
| 候选目录被 .gitignore 忽略 | E4 |
| monorepo 多个子项目各有局部根 | E5 |
| 用户指定其他输出语言 | E6 |
| 目录规模超大（数千文件） | E7 |

## E1 · 非 git 仓库

同步标记与增量 diff 都依赖 git，`scan.mjs` 会在 `warnings` 中提示。触发问询协议 Q3：
说明限制后由用户选择「降级继续（全量生成，不写标记）」或「先 `git init` 再执行」。
用户未表态前不得直接开写。

## E2 · 存量 AGENTS.md 无同步标记

视为人工维护内容，**禁止静默改写**。按 Q2 问询：保留并在同目录另存
（如 `AGENTS.deep-init.md`）、征得同意后改造并入（保留其原有段落表述风格），
或放弃该文件只处理其他目录。

## E3 · 标记哈希不在当前历史

rebase / filter-branch 会使旧哈希失效，此时 `diffSinceMarker` 为 `null`。
处置：对该 scope 整份重新分析并重写，但先读一遍原文件——其中的人工洞察
（约定理由、调试路径等）应在重写中保留。完成后把标记刷新为当前 HEAD。

## E4 · 被 gitignore 忽略的目录

构建产物、依赖目录不该进入知识库。若用户点名要求为其生成，说明理由后拒绝，
并把该目录写入上层 AGENTS.md 的反模式段（「此目录为生成物，勿手改」）。

## E5 · monorepo 局部根

多个子项目各自成体系时，允许每个子项目根使用根模板生成局部根文件；
仓库最外层根的「引用」段改为链接各局部根。判定依据看子项目是否拥有独立的
构建配置与 README，而非仅看目录深度。

## E6 · 输出语言

默认跟随项目既有文档语言（README/注释的主流语言）；项目无既有文档时用中文。
用户明确指定语言时以用户为准。同一项目的所有层级必须保持同一语言。

## E7 · 超大目录

`scan.mjs` 触发 `truncated` 时统计已截断。处置：不要试图遍历全量文件，
改为按 `tree[]` 的 fileCount 从大到小逐域抽样阅读；分层粒度相应变细，
让每层知识库覆盖一个可独立描述的子系统。
