# AGENTS.md 轻量入口规范

`init-deep` 与 `init-arch` 共用本规范。`AGENTS.md` 是默认进入上下文的项目指令入口；`INITDEEP.md` 是按目录读取的知识索引，`ARCHITECTURE.md` 是架构总览，`docs/architecture/` 放需要独立说明的层级约束。每条事实只维护在最贴近它的文件里。

## 根入口骨架

按仓库真实情况填写，省略无内容的行与段落。保持简短，只放项目用途、常用检查命令、必须始终遵守的约定和按任务阅读的路径。链接使用普通 Markdown；避免 `@` 导入语法、全文复制或通过 `CLAUDE.md` 引入详细文件。

```markdown
# <项目名>

<一句话说明用途与主要技术栈。>

## 工作前
- <每次修改都适用的具体约定；没有则省略。>
- <实际可运行的构建或测试命令；没有则省略。>

## 按需阅读
- 初次了解目录和修改入口：[项目知识索引](./INITDEEP.md)。进入某模块时读取该目录的 `INITDEEP.md`（如有）。
- 改变模块依赖或部署边界：[架构总览](./ARCHITECTURE.md)；依主题沿文中链接读取具体层级文件。（仅存在时填写）
```

`INITDEEP.md` 首先列出直接子目录与所承载的任务，并链接下层索引；架构总览列出层级责任、允许的依赖方向、跨层入口和对应详细文件。入口只写「何时读、读哪里」，细节留在目标文件。

## 更新边界

- `init-deep` 负责生成/维护 `INITDEEP.md`，并在根 `AGENTS.md` 增补项目简介、知识索引入口；`init-arch` 负责架构文件及其入口行。只修改自己负责的行，保留其他人工内容与链接。
- 已有 `AGENTS.md` 属于人工维护或存在与目标格式冲突的长文时，先展示缩减后的草案并征得用户确认，才可替换；缺失时创建入口。已有 `CLAUDE.md` 保持原样，若它自动导入详细文件，报告其上下文影响并征求单独授权。
- 保持普通 Markdown 相对链接可达；指向文件而不是整个目录。详细文档改名时同步更新入口链接。避免在子目录自动再建 `AGENTS.md`，由该目录的 `INITDEEP.md` 管理局部导航。

## 依据

- [AGENTS.md 官方站点](https://agents.md/)：跨工具的项目指令入口、应包含项目说明和可执行命令；大型项目允许就地细化。
- [Codex AGENTS.md 指南](https://learn.chatgpt.com/docs/agent-configuration/agents-md)：根到子目录会累计加载指令，默认合并大小有上限。
- [Claude Code 记忆指南](https://code.claude.com/docs/en/memory)：启动时读取项目指令，`@` 导入会在启动时展开；任务特定的长内容宜按需读取。

上述资料描述的是工具的加载行为；本插件采用轻量入口与按需读取策略，以减少每次会话的固定上下文。
