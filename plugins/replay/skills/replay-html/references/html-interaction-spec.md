# 自己看的步进复盘页规范（HTML Interaction & Design Spec）

本规范定义 `replay-html` 单文件 HTML 的版式、交互与视觉约束。对外发布的翻页报告版本见 [replay-post-html 的规范](../../replay-post-html/references/post-html-spec.md)。

---

## 一、 设计哲学：一页只讲一步

读者此刻的状态是「懵」。旧版三栏仪表盘把导航、五要素、证据、角色表同时铺满屏幕，信息密度反而加重了迷雾。新版收敛成**单栏笔记本**：

1. **一屏一步**：主区域只渲染当前步骤，版心 760px，正文 17px、行高 1.8，像在读一页手写笔记；
2. **从上往下就是思考顺序**：先看这里 → 为什么要看这里 → 发现了什么、做了什么 → 最容易想岔的地方 → 所以接下来；
3. **证据默认收起**：原始代码、命令输出和原话放进「想核对原始证据？点开看」折叠块，不打断主线；
4. **术语就地解释**：`glossary` 中的词在正文里自动加虚线，点一下（桌面端悬停）弹出大白话气泡；
5. **全局坐标轻量化**：顶部 3px 进度条 + 底部圆点，目录收进左侧抽屉，需要时再打开。

│━━━━━━━━━━━━━━━━──────────────────────────────│  ← 3px 进度条
│                                              │
│  第 3 步 / 共 8 步 · 阶段二      [关键拍板]  │
│  跑通 qa-bench 压测，揪出 LB 空窗            │  ← 衬线大标题
│  一句话 summary（lead）                      │
│                                              │
│  👀 先看这里   target + 锚点 chips           │
│  🤔 为什么要看这里   段落 / 自动拆分列表     │
│  🔍 发现了什么、做了什么   ① ② ③ 带类型标签 │
│  💡 最容易想岔的地方  ┌你可能以为┬其实是┐    │
│  📎 想核对原始证据？  ▸ 折叠块               │
│  ┌ ➡️ 所以接下来 ───────────────────────┐    │
│  │ hook 段落                            │    │
│  │ [ 懂了，下一步：〈下一步标题〉 → ]   │    │
│  └──────────────────────────────────────┘    │
│ ┌──────────────────────────────────────────┐ │
│ │ ← 上一步      ○ ○ ● ○ ○ ○ ○ ○     下一步 →│ │  ← 浮动底栏

| 画面                 | 内容                                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 开场（`#start`）     | 标题、副标题、元信息；「一开始，其实只想做这件事」「为什么后来会看懵」「出场角色」「怎么看这份复盘」；「从第 1 步开始」按钮 |
| 第 k 步（`#step-k`） | 五要素 + 证据 + 咬合按钮；`status` 为 `decision` / `blocked` 时显示「关键拍板」「卡住了」标签                               |
| 终点（`#end`）       | 已经办妥的、接下来轮到谁（按 `owner` 分组）、你可能还会问（`confusionMatrix`）、小词典；回到开头 / 导出 / 打印              |

`whyLookHere` 与 `background.whyConfusing` 中若出现「1) … 2) …」串写，页面会自动拆成编号列表，前导句保留为段落。

## 三、 交互契约

| 操作                                | 行为                                       |
| ----------------------------------- | ------------------------------------------ |
| `→` / `l`、底栏「下一步」、咬合按钮 | 前进一屏，滚回顶部                         |
| `←` / `h`、底栏「上一步」           | 后退一屏                                   |
| `1`–`9`                             | 直达对应步骤                               |
| `Home` / `End`                      | 回到开场 / 跳到终点                        |
| `t`、顶栏 ≡                         | 打开或关闭目录抽屉                         |
| `Esc`                               | 关闭抽屉、菜单与词条气泡                   |
| URL hash                            | `#start`、`#step-3`、`#end` 可直接分享定位 |

- 当前位置与已读步骤存入 `localStorage`（读写均包在 `try/catch` 中，隐私模式下静默降级），再次打开回到上次位置；
- 菜单提供「导出 Markdown」（按 replay-md 的结构由数据实时拼装）、「打印 / 存为 PDF」（打印时依次展开所有画面与证据）。

## 四、 视觉约束

- **配色**：暖纸底 `#f7f2e8`、墨色正文 `#2b2620`、唯一强调色赤陶橙 `#c0551b`；五要素标签用低饱和的蓝（看哪里）、琥珀（为什么）、绿（做了什么），误区/真相用浅红与浅绿底色对照；深色模式为暖炭底 `#1b1915`，跟随系统并可手动切换；
- **字体**：标题用系统衬线（宋体 / Noto Serif SC），正文用系统无衬线（苹方 / Noto Sans SC），代码用等宽；不引用外部字体；
- **克制**：不使用霓虹色、发光阴影和满屏边框；卡片只用于「误区 vs 真相」「所以接下来」和证据块；emoji 只出现在区块标签上；
- **响应式**：600px 以下误区卡改为上下排列，底栏按钮只保留箭头，保证 390px 宽度无横向滚动；
- **动效**：切换画面 0.38s 上浮淡入，遵守 `prefers-reduced-motion`。
