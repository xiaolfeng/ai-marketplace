1. 未经评审合入的 #280 通过补审 PR #281 回到正常流程，初审发现的 3 处问题与评审指出的 Relay 释放竞态均已修复并合入。

## 背景

AI Gateway 的网关进程与异步 Relay 需要迁移到 core-runtime-sdk/go 提供的统一生命周期组件（Issue #273），目标是让服务在停机、回退与前滚时都能安全排空在途请求。计划中的工作只有两项：完成代码评审，以及在单组件验证环境中完成启停验收。

实际推进中，复杂度主要来自三方面：

1. 上一轮变更 #280 在未经评审的情况下合入主干，关联任务 #273 被同时关闭，需要先恢复评审流程

3. 按发布规范，部署策略调整前必须先完成同版本 1→2→1 多实例演练，且只能在联合演练环境中进行，这又牵出了环境开关与权限的协调

### 2. 修复初审问题并校准停机预算

_阶段一 · 恢复评审流程_ —— 补齐日志字段，将推荐停机宽限期由 5m33s 校准为 5m38s，修正运维手册脚本

**切入点**：Profile 加载日志、网关停机预算计算与运维手册 HANDBOOK-0001（`internal/adapter/profile_loader.go` · `cmd/gateway/runtime.go`）

环境验收依赖日志判断停机行为。如果日志字段缺失或预算计算有误，演练结果本身就不可信，因此修复需要先于验收完成。

- **[修复] 补齐失败日志字段（145e6e3）**：Profile 加载失败时输出配置路径，删除重复赋值，并补充单元测试。
- **[修复] 校准停机预算（c3dc651）**：原实现使用未注明来源的 15s 常量，安全余量只有 5s，低于设计要求的 10s。拆分为摘流等待 10s 与安全余量 10s 两个常量后，推荐宽限期为 338s。
- **[修复] 修正手册脚本（7545aa7）**：修复 HANDBOOK-0001 中 UUIDv7 生成脚本的位运算错误。

> **常见误解**：5m33s 与 5m38s 的差异只影响日志输出。
> **实际情况**：该数值需要落在 Kubernetes 的 340s 强制终止期限之内：10s 摘流 + 318s 排空 + 10s 余量 = 338s，确保进程在被强制终止前 2s 完成退出。

```text
// 10s + 318s (ShutdownTimeout) + 10s = 338s <= 340s (terminationGracePeriodSeconds)
```

_代码层面的问题修复后，需要在真实集群中验证长连接请求在停机过程中的行为。_

### 3. 单组件验收：进程排空正常，部署层存在空窗

_阶段二 · 环境验收_ —— 三轮启停与回退演练中在途请求零中断，但单副本 Recreate 带来 20.9s–46.3s 的 503 空窗

**切入点**：staging-c 环境的网关部署与基线演练脚本（`gateway-staging-c` · `commit 317a817`）

此前的验证只覆盖了健康检查，没有覆盖长流式请求遇到停机、回退与前滚的情况，而这正是 #273 的核心验收项。

- **[发现] 完成三轮启停与回退演练**：在替换瞬间注入长流式请求，旧实例收到终止信号后完整返回响应再退出；Relay 停止领取任务的行为符合预期；本地启动失败时的逆序回滚通过验证。
- **[发现] 识别部署策略层面的空窗**：单副本 Recreate 策略先停止旧实例再启动新实例，替换期间负载均衡没有可用后端，三轮分别出现 20.9s、20.9s、46.3s 的 503。

> **常见误解**：进程能够优雅排空，就意味着发布过程对用户无感。
> **实际情况**：进程排空只保证已建立的请求完成；新请求能否被接住取决于部署策略。单副本 Recreate 下，这段空窗无法通过应用代码消除。

### 7. 厘清环境机制并完善手册

_阶段四 · 演练准备_ —— 确认语音开关由部署白名单控制，回退一次环境方向调整，完成两轮共 9 项手册修订

### 8. 合入 #281 并验证集成环境上线

_阶段五 · 合入与上线_ —— 合入 8897616，重跑主干 CI 完成镜像发布，确认集成环境运行新版本

**切入点**：合入提交、自动写回与集成环境运行状态（`commit 8897616` · `deploy-manifests#1137` · `namespace: gateway-staging`）

#281 合入后会自动构建镜像并发布到日常集成环境，需要确认 CI、镜像发布、配置写回与实例就绪的完整链路。

- **[行动] 合入 #281（8897616）**：在评审批准、CI 通过且无冲突后合入，并确认 #273 未被自动关闭。

## 常见问题

**语音能力已经合入主干，为什么替换演练镜像会将其关闭？**

代码合入与环境开启是两件事：该能力默认关闭，只对部署白名单中的镜像版本开启。

代码中的开关默认值为 false；部署仓库维护一份镜像版本白名单，命中时注入开启配置，未命中时生成空补丁。演练镜像不在白名单内，因此替换期间语音关闭，演练结束切回原镜像后自动恢复。

**为什么跨服务演练不能在单组件验证环境完成？**

单组件验证只需要 staging-c；跨服务的联合排空依赖上游 Worker 排空策略，而该策略只在 staging-b 启用。

请求链路为 Worker → AI Gateway → 模型供应商。其他环境的 Worker 仍使用 Recreate，重启时会中断正在等待网关返回的任务，无法得到有效的联合排空结果。发布规范也约定此类演练统一在 staging-b 排期。

**#281 已合入，为什么 #273 仍保持打开？**

#273 的关闭还依赖两个条件：core-runtime-sdk 正式版发布，以及部署层面的零空窗验收。

当前依赖的 SDK 为预发布版本，正式版发布后需要更新依赖；零空窗替换与超时退出验证已拆分到 #282，计划在多实例演练后与 SDK 升级一并收口。
