# 读者口吻与发布边界（Audience Voice）

本文件是四个复盘技能共用的「读者切换」契约。同一份逆向拆解结果（[reverse-methodology.md](reverse-methodology.md)）和同一套步进数据（[step-chain-schema.md](step-chain-schema.md)），会按读者不同落到两种口吻上：

| 读者                 | 技能                                  | 一句话定位                                         |
| -------------------- | ------------------------------------- | -------------------------------------------------- |
| **自己看（Self）**   | `replay-md` · `replay-html`           | 像坐在旁边的朋友，用大白话把我带出迷雾             |
| **对外发布（Post）** | `replay-post-md` · `replay-post-html` | 像一份正式的事后复盘报告，可以直接发给团队之外的人 |

用户没说给谁看时，按信号判断：出现「我懵了」「给我理顺」「我自己看」「讲人话」走 Self；出现「发出去」「对外」「给团队/老板/客户看」「写成正式报告」「Postmortem」「工程博客」走 Post。两类信号都没有时，先问一句再动手。

---

## 一、 自己看（Self）：尽可能小白

目标读者是「全程点了同意、现在一头雾水的我」。读者不需要懂每条命令，只需要在 5 分钟内知道发生了什么、为什么、现在轮到谁。

1. **第二人称、口语化**：直接说「你当时拍板……」「AI 去翻了……」，允许「为什么突然跑去看集群了？」这类自问自答；
2. **每个术语第一次出现都要解释**：凡是 `selfHeal`、`Recreate`、`ReadinessGate`、`preStop` 这类词，必须同时进入 `glossary`（小词典），用一句生活化的比喻说明它是干什么的；
3. **一个段落只讲一件事**：`whyLookHere`、`leadsToNext` 控制在 2–4 句；长句拆短，数字保留但要说明「这个数字意味着什么」；
4. **先给结论再给细节**：每一步的 `summary` 要能单独读懂，`evidence` 永远默认折叠；
5. **保留真实锚点**：PR 号、SHA、文件路径照样写，但放在「先看这里」的标签里，不塞进叙述句中间；
6. **可以有情绪和安抚**：「别担心，那堆报错只是粘贴命令时的小插曲」这种话是 Self 版的价值所在。

## 二、 对外发布（Post）：稍微正式

目标读者是没参与这场会话的同事、其他团队、技术社区或管理者。读者关心的是「发生了什么、影响多大、为什么这样决策、之后怎么办」。

1. **第三人称或团队视角**：用「团队」「我们」「评审人」，不写「你拍板」「我懵了」；不出现 AI 与用户之间的对话细节，除非它本身就是结论的一部分（如「评审要求不降低验收标准」）；
2. **结论先行（TL;DR）**：开头 3 条以内的要点，读完即可转发；
3. **按工程复盘的骨架组织**：背景 → 影响 → 时间线 → 过程 → 关键决策 → 常见问题 → 现状与后续 → 经验；
4. **术语不必逐个解释**，但同一概念全文只用一个叫法；首次出现的缩写给出全称；
5. **不渲染情绪、不夸大**：去掉「猛猛」「铁证」「魔鬼细节」「惊天」这类修辞，用数字和事实说话；未完成项照实写「待办」，不写成「已就绪」；
6. **决策要写出备选方案**：每个关键决策写清楚「当时有哪些选项、选了哪个、为什么没选另一个」。

### 发布前脱敏清单（Post 必做）

对外版本在写入前逐条核对，命中即处理：

| 类别             | 处理方式                                                                         |
| ---------------- | -------------------------------------------------------------------------------- |
| 人名、昵称、账号 | 替换为角色：「架构评审人」「协作方负责人」「值班同学」；作者署名由用户确认后再写 |
| 内部域名与 IP    | 替换为 `<internal-gateway>`、`<cluster-b>` 这类占位，或只保留环境代号            |
| 凭据与令牌       | 一律删除；连「签出了 kubeconfig 的路径」也只写「临时凭据」                       |
| 内部群聊原话     | 改写为转述，不贴截图式原文；必要时只保留决策结论                                 |
| 未公开的业务数据 | 用比例、量级或区间代替绝对值，用户明确允许时才保留原数                           |
| 仓库与 PR 链接   | 私有仓库保留编号但不写可点击的内部链接；公开仓库可保留                           |

脱敏后在 `publication.redactionNote` 里写一句「本文已省略/替换了哪些类别的信息」，页面底部会展示出来。

## 三、 同一句话的两种写法

| 字段              | Self（自己看）                                                                  | Post（对外发布）                                                                           |
| ----------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `whyLookHere`     | 前一个流程没等任何人点 Approve，就自己把 #145 合进了 main，还顺手把 #140 关了！ | 上一轮变更 #145 在未经评审的情况下合入主干，关联任务 #140 被同时关闭。                     |
| `confusionBuster` | 你可能以为：合进 main 了就算上线了。其实：功能还被一个默认关着的开关挡着。      | 常见误解：代码合入即代表功能上线。实际上该能力由默认关闭的配置开关控制，按环境白名单开启。 |
| `leadsToNext`     | 代码都修好了，可新问题来了——停机时请求到底会不会断？我们得去真集群里试试。      | 代码层面问题清零后，下一步需要在真实集群中验证停机期间的在途请求行为。                     |
