# Replay Markdown —— 逆向复盘走读手册生成器

当 AI 在长对话或多轮任务里一路狂奔（改代码、跑测试、查集群、提 PR、建 Issue、发团队通知），而你在旁边一路点「同意 / 继续」，事后面对几千行记录不知所措时，本技能负责**从终局倒推因果，再按正向关卡带你一步一步走出来**。

与 [replay-html](../replay-html/SKILL.md) 的分工：
本技能产出**结构化 Markdown 走读文档**（适合沉淀到仓库、贴入 Issue/PR/团队知识库或线性阅读）；若用户希望在浏览器中像闯关一样点击「下一步」交互式推进，使用 `replay-html`（或两者配合产出）。

## 铁律

1. **先从终局倒推，绝不顺着抄流水账。** 动笔前必须按 [../_shared/reverse-methodology.md](../_shared/reverse-methodology.md) 盘点终局产物，逆向追查每一项动作的触发原因，并将命令报错重试、后台等待穿插、方向折返等噪音折叠收拢。
2. **严守单步五要素契约。** 每一个 Step（关卡）必须完整回答 [../_shared/step-chain-schema.md](../_shared/step-chain-schema.md) 规定的五个问题：**① 第一步看什么 → ② 为什么要看这里 → ③ 在这里发现了什么 & AI 做了什么 → ④ 关键转折/认知破雾 → ⑤ 从这里引申到哪里**。
3. **步步首尾咬合。** Step $k$ 的「🔗 从这里引申到哪里」必须精确指向 Step $k+1$ 的「📍 第一步看什么」；中间严禁出现无铺垫的话题跳跃。
4. **专治「人类懵逼点」。** 凡是原会话中用户追问过「为什么」、连点同意跳过长分析、或发生过方案撤回（如 `git revert`）的地方，必须在对应 Step 及文末「高频混淆概念破雾表」中用大白话讲透底层机制。
5. **锚点保真，人话先行。** 先用直白中文讲清工程因果，再附上精确的 PR/Issue 编号、Commit SHA、文件路径行号与实测数据；长代码或原始命令输出一律放进 `<details>` 折叠块，不打断主线阅读。

## 执行步骤

### 1. 采集与盘点终局（Inventory）

确认复盘对象来源（当前会话上下文、本地/远程 `.claude/projects/**/*.jsonl` 会话文件、Git 提交与 PR 历史，或用户粘贴的记录）：

1. 提取**初始起因**（一开始本来只打算解决什么问题？）；
2. 提取**终局账单**（最终合入了什么、新开了什么 PR/Issue、改了哪个环境、还剩什么阻塞）；
3. 标记会话中的**人类困惑信号**（追问句、打断/撤回处、跨多仓跳跃处）。

### 2. 逆向构建 5–9 步因果链（Backward Tracing）

按 [../_shared/reverse-methodology.md](../_shared/reverse-methodology.md) 从终局往回推导：

- 将成百上千次工具调用收敛为 **5–9 个认知关卡（Step）**；
- 执行**四类噪音折叠**（工具语法试错、后台等待穿插、方向折返、话术打磨全部收进关卡内部插曲）；
- 校验每两步之间的**首尾咬合关系**。

### 3. 按五要素撰写 Markdown 走读稿（Drafting）

严格按照 [references/markdown-structure.md](references/markdown-structure.md) 的排版模板生成文档：

1. **全景背景与阅读罗盘**：一句话目标 + 为什么这次会让人懵 + 涉及仓库/环境角色表；
2. **因果主线全景图**：用清晰的 ASCII / Mermaid 链路图画出 `Step 1 ──(引申原因)──► Step 2 ... ──► Step N`；
3. **逐关走读（Step 1 ~ Step N）**：每关带进度坐标条（如 `[●──◉──○──○]`），依次展开五要素，必要时附 `<details>` 原始证据；
4. **灵魂追问与概念破雾表**：把最绕的概念对（如「代码合入 vs 环境特性开启」「单组件演练环境 vs 联合排空环境」）做成对照卡片；
5. **终局账单与下一步接力表**：区分「✅ 已彻底闭环」与「⏳ 待外部配合 / 明日执行」。

## 特殊情况速查

| 信号                                            | 处置                                                                                | 条目 |
| ----------------------------------------------- | ----------------------------------------------------------------------------------- | ---- |
| 用户给出了远程机器或指定 session 名称           | 先通过 SSH / 本地路径定位对应的 `.jsonl` 或历史记录，提取用户与 AI 关键节点后再拆解 | E1   |
| 会话经过了 Context 压缩（含 Summary 续接）      | 将头部 Summary 中的前半场脉络与下半场原始记录无缝拼接为同一条完整因果链             | E2   |
| 复盘对象跨 3 个以上仓库或环境                   | 在「全景背景」必须先立一张「多仓/多环境职责对照表」，防止读者在阅读中途搞混名字     | E3   |
| 用户不仅要 Markdown，还想要可点击步进的 HTML 页 | 先完成或共用同一份五要素数据模型，联动调用 `replay-html` 产出双份交付物             | E4   |

## 自检

- [ ] 是否从终局倒推收敛为 5–9 个关卡，而不是按时间顺序抄写工具调用流水账？
- [ ] 每个 Step 是否都包含完整的五要素（看哪里 / 为什么看 / 做了什么 / 认知破雾 / 引申到哪）？
- [ ] 相邻 Step 的「引申到哪里」与下一步的「第一步看什么」是否严丝合缝咬合？
- [ ] 用户在原对话中追问或混淆的问题，是否都在「认知破雾」和文末对照表中用大白话讲透了？
- [ ] 关键 PR/Issue 号、Commit SHA、配置键与实测数字是否准确无误且未编造？
