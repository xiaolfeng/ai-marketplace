# Markdown 复盘走读稿排版规范（Markdown Structure Guide）

本规范定义 `replay-md`（自己看·小白版）交付文档的版式骨架与视觉呼吸感准则。目标是让一位原本满头雾水的读者，从第一行往下读时像有人在旁边指着屏幕带路一样轻松顺畅。口吻要求见 [../../_shared/audience-voice.md](../../_shared/audience-voice.md) 的 Self 一节；需要对外发布的正式报告请改用 `replay-post-md`。

---

## 二、 排版与叙事四项纪律

1. **进度坐标条必不可少**：每个 Step 标题下方加上 `进度：[●──◉──○──○] k/N`，让读者在长文中时刻知道自己走到了整条链路的几分之几。
2. **「先看哪里」用引用块高亮**：让读者扫视页面时，第一眼就能抓到每一关的视觉锚点。
3. **折叠重型证据**：超过 6 行的代码段、Shell 脚本或审查原文，一律收进 `<details><summary>📂 展开查看本步原始证据...</summary>...</details>`，保证主干阅读一气呵成。
4. **严禁生造术语**：复盘的使命是**降维解惑**，不是炫技。遇到平台专有机制（如 `Argo selfHeal`、`Pod ReadinessGate`、`令牌并发上限`），第一次出现时必须在括号里用一句大白话解释它干什么用。
5. **小词典兜底**：正文括号里解释过的术语，统一再收进文末「小词典」表，用比喻讲，禁止用术语解释术语；词条通常 6–12 个。
6. **30 秒看懂必须能单独转述**：三句话里不出现 PR 号、SHA 和英文术语，读者读完就能跟别人说清楚这件事。
