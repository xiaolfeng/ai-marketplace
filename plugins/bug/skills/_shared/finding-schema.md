# 发现与修复的输出契约

三份技能共用这一份结构：`find-bug` / `find-security-bug` 出发现清单，
`fix-bug` 引用同一套 ID 写修复记录。禁止在 SKILL.md 里再复制一份模板。

## 发现 ID

| 前缀 | 技能              | 示例   |
| ---- | ----------------- | ------ |
| `Q-` | find-bug          | `Q-01` |
| `S-` | find-security-bug | `S-01` |

序号两位、按本轮报告出现顺序递增。同一根因只占一条；相关症状写进该条的
「影响」，不要拆成三条看起来很多的发现。

## 严重度

评的是**在本范围内一旦成立的后果**，不是「写得丑」的程度。

| 级   | 质量缺陷                                              | 安全缺陷                                           |
| ---- | ----------------------------------------------------- | -------------------------------------------------- |
| 阻断 | 默认路径崩溃、数据丢失、错误金额/库存、任务彻底不可用 | 未授权即可 RCE、认证绕过、批量敏感数据可读         |
| 高   | 主路径结果错误、明显的丢失更新/死锁、资源必然泄漏     | 低权限即可越权读写、注入成立但需登录、加密形同虚设 |
| 中   | 边界条件错误、部分调用方会踩、可降级的失败处理漏洞    | 需特定角色或少见配置、有部分缓解仍可绕             |
| 低   | 难触发、影响面窄、仅可观测性受损                      | 有限信息泄露、攻击窗口极窄                         |

升到「阻断 / 高」必须写清**谁会踩到、踩到会怎样**；写不出就降一档。

## 置信度

与 research 插件同一套词，但判据换成代码证据（详见
[evidence.md](./evidence.md)）：

| 等级 | 何时用                                                   |
| ---- | -------------------------------------------------------- |
| 确定 | 一级证据：失败测试、可运行复现、或堆栈精确落到行         |
| 倾向 | 二级证据：源到汇数据流完整、路径看起来可达，但还没跑起来 |
| 存疑 | 三级证据：局部反模式，入口或消毒情况没追完               |

没有新证据不许靠措辞升级。空报告合法——没找到就写覆盖范围与缺口，
禁止为了显得干了活硬造条目。

## 发现清单模板（find-*）

```markdown
## 范围

- 目标：<文件 / diff / 模块>
- 口径：质量 | 安全
- 假设：<用户没说清时声明的默认假设>
- 未看：<明确排除的目录、生成物、依赖实现>

## 发现清单

### Q-01. <一句话标题，含后果>

- 类别：<taxonomy 编号，如 C1 正确性 / A01 访问控制>
- 严重度：阻断 | 高 | 中 | 低
- 置信度：确定 | 倾向 | 存疑
- 位置：`path:start-end`（函数名）
- 证据：<一级/二级/三级 + 引用片段或数据流>
- 影响：<谁会踩到、踩到会怎样>
- 为何成立：<机制，三句内>
- 为何可能不成立：<反证；没有就写「未见反证」>
- 建议方向：<改哪类检查 / 哪条不变量；不给完整补丁>

## 转交

质量审查里撞上的安全形状问题、或安全审查里撞上的纯质量问题，只记一行
ID + 一句话 + 应走的技能，不在本报告里展开成正式发现。

## 排除

查过但不成立的嫌疑，各写一行排除原因，防止下一轮重复踩。

## 覆盖缺口

没读到的层、没跑到的路径、静态分析固有的不可达，如实地写。
```

「建议方向」只指出不变量或缺失的检查，不把 `fix-bug` 的补丁写进发现报告。
用户同一句话里说了「找完就修」时：先完整交付本报告，再进入 `fix-bug`。

## 修复记录模板（fix-bug）

```markdown
## 复现

- 失败信号：<测试名 / 堆栈顶 / 日志>
- 最小复现：<步骤或用例>
- 对应发现：<Q-xx / S-xx / 无编号的现场故障>

## 根因

- 假说：<一句话>
- 证伪实验：<只改一个变量的结果>
- 机制：<坏值从哪来、在哪变成错的、为何现有检查没拦住>

## 修复

- 改动：<文件与不变量，对应最小 diff>
- 故意不改：<顺手重构、风格、无关优化 —— 列出并保持原样>

## 验证

- 原复现：<已失败 → 现通过>
- 相邻回归：<跑过哪些相关测试 / 为何没条件跑、残留风险是什么>

## 未覆盖风险

三轮假说仍打不穿时写在这里，不要再叠第四块补丁。
```
