# Find Security Bug —— 安全缺陷发现

在用户授权的代码范围内找跨越信任边界的缺陷。
产出是一份能被 `fix-bug` 接走的安全发现清单：有身份模型、有数据流、
有 OWASP/CWE 类别，**没有**武器化利用。

与姊妹技能的分工：

- 正确性、并发、资源、契约等不跨越信任边界的问题 →
  [find-bug](../find-bug/SKILL.md)
- 用户要关上漏洞 → [fix-bug](../fix-bug/SKILL.md)

完整示范见 [examples/scenario.md](examples/scenario.md)。
输出结构与取证规则：
[finding-schema.md](../_shared/finding-schema.md) ·
[evidence.md](../_shared/evidence.md)。
类别细则：[references/security-taxonomy.md](references/security-taxonomy.md)。

## 铁律

1. **先授权后分析。** 默认只读本仓库用户指定的路径；未声明的远程主机、
   生产环境、他人系统不碰。范围说不清就先问，或声明「仅静态阅读本仓库」。
2. **取证不等于利用。** 写输入类别与被绕过的检查，不写可直接打的 payload、
   exploit、攻击命令或逐步入侵教程。
3. **身份模型必出场。** 每条发现写清攻击者要什么身份、要不要跨用户；
   写不出就降为存疑。
4. **只发现不修复。** 建议方向指出该补哪类授权/参数化/校验，不给完整补丁。
5. **空报告合法。** 没找到可达漏洞就写覆盖缺口；禁止把质量问题或 CVE 清单
   灌进来充数。

## 执行步骤

### 1. 钉范围与身份

开查前对齐：

| 要素     | 要回答的                                       |
| -------- | ---------------------------------------------- |
| 资产     | 哪些服务、API、页面、作业是本次目标            |
| 信任边界 | 匿名、登录用户、其他租户、管理员、内部 worker  |
| 授权     | 仅静态读仓库，还是允许对本地开发实例做无害复现 |
| 明确禁止 | 生产、客户数据、未声明主机                     |

用户说「帮我打一下这个线上域名」而没有书面授权 → 拒绝，退回静态阅读本仓库。
允许本地无害复现时，也只构造证明控制被绕过的最小输入类别，不保存利用脚本。

### 2. 画信任边界

只读入口（路由、handler、队列消费者、反序列化点、模板渲染、文件/URL 抓取），
标出：

- 不可信输入从哪进来；
- 认证/授权检查挂在哪一层、有没有漏网路由；
- 机密存在哪（配置、代码、环境）。

然后按 taxonomy 的优先顺序审查，而不是按 Top 10 序号从 A01 背到 A10。

### 3. 取证

每条嫌疑必须能填完：

```
源 → 路径 → 汇 → 现有消毒/授权 → 所需身份
```

源或汇任缺、或身份写不清：最多标存疑，或放进覆盖缺口。
工具扫描命中只当线索，要再走一遍数据流。

依赖里的已知 CVE：没有本仓库可达路径时写进覆盖缺口，建议 SCA，
不要伪装成本轮已经证实的利用链。

### 4. 出报告

按 finding-schema 模板，ID 用 `S-`，类别写 `A0x:2025 …（CWE-…）`。
密钥只报文件与变量名，不把密钥值抄进报告。

用户说「找完就修」：先交完整安全发现清单，再进 `fix-bug`。
`fix-bug` 修安全条目时仍遵守「验证用回归、不用利用脚本」。

## 特殊情况速查

| 信号                          | 处置                                           | 条目 |
| ----------------------------- | ---------------------------------------------- | ---- |
| 未授权的远程目标 / 要 exploit | 拒绝，说明本技能只做授权范围内的缺陷发现       | E1   |
| 其实是空指针/竞态/泄漏        | 转 `find-bug`；仅当跨越安全边界才升格并写理由  | E2   |
| 用户要补丁                    | 转 `fix-bug`，把 `S-xx` 一并带走               | E3   |
| 只有扫描器规则名没有数据流    | 降为线索，不进发现清单                         | E4   |
| 硬编码密钥                    | 报位置与变量名，建议轮换；值不进报告           | E5   |
| 零发现                        | 空清单 + 覆盖缺口（未做动态测试、未跑 SCA 等） | E6   |

## 自检

- [ ] 授权范围写在报告开头，没有越权探测
- [ ] 每条都有身份模型、数据流、OWASP/CWE 类别
- [ ] 正文没有 payload、exploit、可复制攻击命令
- [ ] 密钥值没有被复制进报告
- [ ] 质量问题只出现在转交段（或有明确升格理由）
- [ ] 没有把依赖 CVE 清单当成已证实发现
