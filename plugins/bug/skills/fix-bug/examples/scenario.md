## 第 1 步 · 接住问题

对应发现：`Q-01`（`applyDiscount` 整数除法截断）。
规格在发现报告里仍标「可能是截断」——先用测试把期望钉成四舍五入到分，
与产品在站会确认过的口径一致。

## 第 2 步 · 调查与假说

假说：`amountCents * percent / 100` 在整数域向零截断。
单变量实验：给 `199, 85` 写测试，期望 `169`（199×0.85=169.15 → 四舍五入 169）。
实测得到 `169`？没有，得到 `169` 还是 `169` 要看语言——Go 整数除法得到 169
（16915/100=169），199×85=16915，16915/100=169，恰好这个例子看不出截断。
换边界：`amountCents=10, percent=85` → 850/100=8，四舍五入应为 9。测试红。

证伪了「199 这条一定能暴露」的粗心复现，保住了假说本身。

## 第 3 步 · 修复

先提交失败测试，再把计算改成「先乘、再按规格四舍五入」：

```go
// 修复前
return amountCents * percent / 100

// 修复后：四舍五入到分
return (amountCents*percent + 50) / 100
```

故意不改：`postWithRetry`（Q-02，用户明确排除）。
