# Find Bug —— 质量缺陷发现

只找会在运行时让结果出错、状态损坏或进程崩溃的问题。
报告的终点是一份能被 `fix-bug` 接走的发现清单，不是补丁，也不是风格意见。

与姊妹技能的分工：

- 注入、越权、密钥、CSRF 等跨越信任边界的问题 →
  [find-security-bug](../find-security-bug/SKILL.md)
- 已经有复现或用户要动手改 → [fix-bug](../fix-bug/SKILL.md)

完整示范见 [examples/scenario.md](examples/scenario.md)。
输出结构与证据规则是全插件共用的：
[finding-schema.md](../_shared/finding-schema.md) ·
[evidence.md](../_shared/evidence.md)。

## 铁律

1. **范围先行。** 先钉死看哪些文件/diff、以哪份规格为准；缺规格就声明假设再开工。
2. **先读再判。** 每条发现必须能指到路径与行号；模式匹配只是线索，要补数据流。
3. **只发现不修复。** 建议方向只写不变量或缺失检查，不改业务代码、不给完整补丁。
4. **空报告合法。** 没找到就写覆盖范围与缺口；禁止为了显得干活而硬造条目。
5. **质量与安全分家。** 安全形状的问题只转交一行，不在本报告展开。

## 执行步骤

### 1. 圈范围

用户常只丢一句「看看这块」。开查前对齐四件事（缺的就声明默认假设）：

| 要素 | 要回答的                                       |
| ---- | ---------------------------------------------- |
| 目标 | 文件、diff、模块，还是整仓浅扫                 |
| 规格 | 测试、注释、ticket、还是「按代码自称的不变量」 |
| 深度 | 主路径 + 错误路径，还是连并发/资源也看         |
| 产出 | 发现清单（默认）                               |

整仓浅扫时先读入口与状态写入点，不要从工具生成物或 `node_modules` 开刀。
范围过大就先切一块，并在报告「未看」里写清切掉了什么。

### 2. 建图

用只读工具把目标读完，画出三张草图（可以只在脑子里，复杂时写进范围段）：

1. **入口**：谁调用这些函数、默认参数是什么；
2. **状态**：哪些可变数据被写入、写入是否有顺序/锁；
3. **失败**：错误怎么传播，有没有被吞。

分类清单见 [references/quality-taxonomy.md](references/quality-taxonomy.md)，
按 C1→C6 过一遍，但只在草图上有对应结构时深入——没有共享状态就不要硬找竞态。

### 3. 取证

对每个嫌疑走 [evidence.md](../_shared/evidence.md) 的数据流句式。
能写到源和汇的进清单；写不全的进「排除」或「覆盖缺口」。

优先顺序（同一轮时间有限时）：

1. 会写出错误结果或损坏状态的主路径（C1、C6）；
2. 默认输入就会崩的空值与资源问题（C1、C3）；
3. 现有并发模型下真会发生的竞态（C2）；
4. 契约与错误处理（C4、C5）。

### 4. 出报告

按 [finding-schema.md](../_shared/finding-schema.md) 的发现清单模板交付，
ID 用 `Q-`。同一根因合并；建议方向禁止展开成 diff。

用户同一句话里说了「找完就修」：先完整交付本报告，再切换 `fix-bug`，
不要边找边改——改动会污染下一处判断。

## 特殊情况速查

| 信号                          | 处置                                                  | 条目 |
| ----------------------------- | ----------------------------------------------------- | ---- |
| 用户要的其实是安全审查        | 说明边界并转 `find-security-bug`                      | E1   |
| 已经有堆栈 / 失败测试且要补丁 | 转 `fix-bug`，可把当前观察写成临时发现一并带走        | E2   |
| 只有风格、命名、格式意见      | 明确拒绝报成缺陷，必要时建议格式化工具                | E3   |
| 范围是整仓且无入口线索        | 先切到写入路径与公开 API，浅扫结论标「倾向/存疑」为主 | E4   |
| 规格互相打架                  | 并列两种解读，相关条目整体标存疑                      | E5   |
| 零缺陷                        | 交空清单 + 覆盖缺口，不要找「可改进」凑数             | E6   |

## 自检

- [ ] 范围、规格假设、未看目录都写在报告里
- [ ] 每条都有位置、机制、影响、反证
- [ ] 置信度与证据等级匹配，没有靠措辞升级
- [ ] 没有给出完整补丁或改动业务代码
- [ ] 安全形状的问题只出现在转交段
- [ ] 没有风格/格式条目混进发现清单
