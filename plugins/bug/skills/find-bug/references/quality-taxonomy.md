# 质量缺陷分类

配合 `find-bug` 使用：正文只留工作流，本手册回答「这条该打哪类、别跟安全抢」。

分类改编自常见缺陷本体论（正确性 / 并发 / 资源 / 契约 / 边界），**不是**
OWASP。安全形状的问题只记一行转交，不在本表展开。

## C1 正确性

结果与规格或调用方不变量不符。

| 信号                              | 要追的                  | 常见假阳性                       |
| --------------------------------- | ----------------------- | -------------------------------- |
| 条件写反、漏分支、off-by-one      | 边界值与循环不变量      | 故意的哨兵值、文档写明的半开区间 |
| 空值解引用、未初始化读            | 该路径是否真的能走到空  | 语言层智能转换 / 明确的前置检查  |
| 错误的单位、时区、精度、舍入      | 规格里的单位与舍入规则  | 展示层格式化（非计算）           |
| 用错集合/映射键导致丢数据或串数据 | 键的相等性与大小写/编码 | 有意去重                         |

**升到阻断/高的门槛：** 默认输入或主路径就会产出错误结果或崩溃。

## C2 并发与时序

多线程、异步、多进程、多实例下才出现的错误。

| 信号                 | 要追的                              | 常见假阳性                 |
| -------------------- | ----------------------------------- | -------------------------- |
| 共享可变状态无同步   | 谁写、谁读、锁/队列是否覆盖这条路径 | 单线程事件循环里的局部变量 |
| 检查后使用（TOCTOU） | 检查与使用之间是否可插入变更        | 单线程且无让出点           |
| 死锁 / 锁顺序不一致  | 锁的获取顺序是否成环                | 文档化的层级锁且本路径遵守 |
| 超时、取消、重试叠加 | 取消是否真正停止副作用              | 只读重试                   |

没有共享或没有并发入口时，不要把「将来可能并发」写成发现。

## C3 资源生命周期

打开的东西没关上，或关上之后还在用。

| 信号                                                     | 要追的                   | 常见假阳性                      |
| -------------------------------------------------------- | ------------------------ | ------------------------------- |
| 句柄/连接/文件未关闭                                     | 所有返回路径，含异常路径 | 由上层容器管理的生命周期        |
| use-after-free、双重释放（含逻辑层的「释放后再读缓存」） | 所有权转移点             | RAII / 语言层自动回收且无裸指针 |
| 连接池/缓存无限增长                                      | 驱逐策略与上限           | 有界结构且有测试锁死上限        |

短生命周期的请求内对象，只要函数返回即释放，不必当成泄漏。

## C4 契约与边界

函数、模块、服务之间的隐含约定被打破。

| 信号                                         | 要追的                         | 常见假阳性                       |
| -------------------------------------------- | ------------------------------ | -------------------------------- |
| 调用方假设非空 / 已排序 / 已授权，实现不保证 | 注释、类型、测试是否把约定写死 | 私有函数且唯一调用方已保证       |
| 分页、过滤、排序参数被截断或忽略             | API 文档与实现是否同口径       | 明确的最大页大小且返回了截断信号 |
| 时间解析、路径拼接、编码往返损失             | 往返一次是否还能得到原值       | 有意的规范化                     |

跨服务契约（HTTP 状态、错误码语义）也归此类，不要只看本文件。

## C5 错误处理与可观测性

失败被吞掉、被转成成功、或 succeded 却没法诊断。

| 信号                           | 要追的                             | 常见假阳性             |
| ------------------------------ | ---------------------------------- | ---------------------- |
| 空 catch、返回默认值假装成功   | 调用方是否依赖这个返回当「真成功」 | 明确的降级路径且有指标 |
| 错误码丢失 / 被覆盖            | 原始错误是否还在链上               | 隐私原因故意剥离细节   |
| 日志没有关键字段，出事无法定位 | 现有告警/追踪是否依赖这些字段      | 调试日志级别的噪音     |

「日志不够漂亮」不是缺陷；「这条失败路径没有任何信号」才是。

## C6 状态与幂等

写操作被重试、被并发、被乱序时状态机走歪。

| 信号                              | 要追的                           | 常见假阳性               |
| --------------------------------- | -------------------------------- | ------------------------ |
| 非幂等的重试导致重复扣款/重复创建 | 是否有幂等键或唯一约束           | 只读接口                 |
| 状态机跳步、回退到非法状态        | 所有合法转移是否穷尽             | 测试夹具里的故意非法状态 |
| 读己之写在副本上失败              | 一致性模型是否被调用方假设为线性 | 文档已声明最终一致       |

## 排除：不是本技能的菜

| 现象                                         | 去向                                         |
| -------------------------------------------- | -------------------------------------------- |
| 注入、越权、CSRF、SSRF、硬编码密钥、反序列化 | 转交 `find-security-bug`                     |
| 已经有堆栈 / 失败测试、用户要的是补丁        | 转交 `fix-bug`                               |
| 命名、格式、注释、导入排序、「不够优雅」     | 不报；需要的话让用户走格式化工具             |
| 架构选型、要不要换库                         | `research` / `engineering-design`            |
| 测试覆盖率数字本身                           | 只在它让某条发现无法证实或证伪时写入覆盖缺口 |
