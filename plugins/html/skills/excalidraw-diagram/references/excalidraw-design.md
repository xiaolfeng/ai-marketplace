# Excalidraw 手绘白板设计与几何规范

本文件是 Excalidraw 图表生成的核心设计规范。遵循手绘白板（Hand-drawn Whiteboard）视觉语言，先规划语义走廊与信息分层，再计算图元坐标与连线端点。

## 1. 白板手绘美学原则

- **手绘自然感（Roughness）**：默认保持 `roughness: 1`。既具备手绘白板的亲和力与草图质感，又避免过度杂乱变形（禁随意设为 0 导致机械僵硬，亦不可设为 2 导致结构散架）；
- **线条粗细（StrokeWidth）**：标准图元与主流程连线建议 `strokeWidth: 2`；外层分组容器或弱依赖线使用 `strokeWidth: 1`；重点高亮节点使用 `strokeWidth: 3`；
- **手写字体（FontFamily）**：纯文本与标签强制统一使用手写风格字体（`fontFamily: 5` Excalifont，兼容 Virgil 与系统手写体），字号通常在 `16–22px`，标题 `28–36px`；
- **填充质感（FillStyle）**：
  - `solid`：大块背景底衬，色彩均匀温和；
  - `hachure`：手绘斜线阴影，适合区分不同子域或强调模块；
  - `cross-hatch`：交叉网格排线，适合存储、归档或安全隔离层。

## 2. 图元尺寸与文本排版计算

图元尺寸应由文字量、业务职责与连线密度共同决定，严禁文字爆框或贴边：

| 内容类型 | 推荐宽度 (Width) | 推荐高度 (Height) | 适用场景 |
| --- | --- | --- | --- |
| 简短词汇（1-2词） | `110–140px` | `55–70px` | 起止状态、简单动作、叶子节点 |
| 标准短语（3-5词） | `160–200px` | `75–95px` | 核心服务模块、标准业务步骤 |
| 复合卡片（带说明） | `220–280px` | `100–140px` | 带有数据表名、多端口职责节点 |
| 菱形分支网关 | `100–140px` | `100–140px` | 条件分支决策点（宽高保持一致） |
| 容器/区域边界 | `400–800px` | `240–500px` | 网络子网、微服务集群、泳道区域 |

### 文本尺寸估算规则

```javascript
// 单行文本宽度估算
const approxWidth = text.length * fontSize * 0.65 + 32;

// 多行文本高度估算
const lineCount = text.split('\n').length;
const approxHeight = lineCount * fontSize * 1.35 + 24;
```

图元宽高必须严格大于文本估算宽高，四周保留至少 `16px` 内边距（Padding）。

## 3. 走线与箭头几何学

- **相对坐标系（Points Array）**：
  - 连线与箭头的 `x, y` 代表起点绝对坐标；
  - `points` 数组中的点均为相对起点 `(x, y)` 的偏移量，第一个点始终为 `[0, 0]`；
  - 水平正交走向：`points: [[0, 0], [deltaX, 0]]`；
  - 垂直正交走向：`points: [[0, 0], [0, deltaY]]`；
  - 弯折走向（L型/Z型）：`points: [[0, 0], [midX, 0], [midX, deltaY]]`。
- **吸附与缓冲**：
  - 连线起点与终点必须精准贴附对应图元的外边框（边缘中点或角落），不得悬空，亦不得过深插卡片内部；
  - 箭头在进入目标卡片前，保留至少 `20px` 的直行缓冲段。
- **连线标签**：
  - 标签文本使用独立 `text` 元素承载；
  - 放置在线条中点上方 `12–16px`（水平线）或侧边 `12–16px`（垂直线），切忌直接压在线条之上。

## 4. 语义色彩体系

为保证明暗双主题下均具备优良对比度，遵循低饱和粉彩语义盘：

| 语义角色 | 浅色模式背景 | 深色模式渲染 | 描边色彩 | 典型场景 |
| --- | --- | --- | --- | --- |
| 客户端与接入 | `#a5d8ff` (浅蓝) | `#1e3a8a` / 半透蓝 | `#1e1e1e` / `#38bdf8` | 用户终端、移动端、Web应用、网关接入 |
| 服务与业务流 | `#b2f2bb` (浅绿) | `#064e3b` / 半透绿 | `#1e1e1e` / `#34d399` | 微服务组件、核心处理环节、业务流水线 |
| 判定与中间件 | `#ffd43b` (金黄) | `#78350f` / 半透黄 | `#1e1e1e` / `#fbbf24` | 判定网关、分布式缓存、消息队列、负载均衡 |
| 告警与异常流 | `#ffc9c9` (绯红) | `#881337` / 半透红 | `#1e1e1e` / `#f87171` | 熔断降级、参数校验失败、回滚事务、告警通道 |
| 数据持久与安全 | `#d0bfff` (浅紫) | `#4c1d95` / 半透紫 | `#1e1e1e` / `#a78bfa` | 主备数据库、冷热存储、鉴权中心、加密金库 |

## 5. 间距与全局留白建议

| 间距维度 | 推荐数值 | 说明 |
| --- | --- | --- |
| 横向流转间距 (Horizontal Gap) | `180–240px` | 为连线、标签与箭头预留清晰走廊 |
| 纵向分层间距 (Vertical Gap) | `100–150px` | 保证层级分明，避免连线交叉拥挤 |
| 全局视口边距 (Canvas Padding) | `60–80px` | 视口边界留白，防止最外层图元贴紧画板边缘 |
| 区域容器内边距 (Container Padding) | `30–45px` | 分组容器边界与内部第一个图元的距离 |

## 6. 九类白板图表核心设计范式

1. **流程图 (Flowchart)**：椭圆起止 + 矩形处理 + 菱形判定，单一主干居中，异常分支向侧面或下方折回；
2. **系统架构图 (Architecture)**：左侧客户端接入 → 中间网关与核心微服务 → 右侧或底部数据库与中间件；
3. **泳道业务流 (Swimlane)**：顶部纵向角色横幅（用户、业务网关、订单系统、支付系统），纵向泳道内严格放置对应职责卡片，跨泳道连线清晰；
4. **思维导图 (Mind Map)**：核心主题居中，发散放射状分支（3-6个主分支），主分支使用不同手绘配色；
5. **时序图 (Sequence)**：顶部水平平铺角色对象，垂直延伸虚线生命线，水平箭头标明请求与返回时序；
6. **ER 实体关系图 (ER Diagram)**：主实体矩形（标明主键 PK 与外键 FK），关联关系线标明 `1:1`、`1:N`、`N:M` 基数；
7. **类图 (Class Diagram)**：矩形分为三段（类名、属性、方法），继承空心箭头、依赖虚线箭头；
8. **数据流图 (DFD)**：外部实体矩形、处理逻辑圆形/圆角矩形、数据存储双横线/开放矩形，只反映数据流动不反映执行顺序；
9. **组件依赖关系图 (Relationship)**：网格对齐布局，组件间带有明确动词标签的连线。
