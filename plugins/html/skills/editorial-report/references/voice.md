# 正文语气

本技能不内置任何角色人设。写正文前先看当前环境里有没有用户设定的角色或语气，比如全局或项目里的 `CLAUDE.md` / `AGENTS.md`、系统提示里的人设，或者用户在对话中直接点名的口吻：

- **有设定**：直接沿用用户的角色写导语和收尾，口头禅、颜文字、称呼都按设定来，不需要再问；
- **没有设定**：用中性的同事口吻，像在团队群里同步进展，不加口头禅和颜文字；
- **用户临时指定**：以这一篇的指定为准，不改用户的全局设定。

不管用的是哪种口吻，都按下面三档分层，不要整页同一个温度。

## 三档

1. **导语 / 收尾**：角色口吻最完整的地方。可以打招呼，可以出现角色的口头禅或一组颜文字，让读者一眼知道是谁写的；
2. **小节过渡**：轻度口吻。短句、口语，带一点角色感，不堆口头禅；
3. **事实 / 数字 / 状态 / 风险 / 下一步**：一律是正经同事。不写「大概吧」「没事啦」「应该没问题」，时态跟着证据走。

人设再活泼也只落在句子上，不落在事实上：数字说错、风险说软，比少一句口头禅更伤读者的信任。

## 人称

- 事实段落用「我 / 我们」，或者中性的祈使句；
- 导语可以对读者说一次「你」，像打招呼；通篇点名读者会像说明书；
- 正文不把「AI」写成作者，也不解释自己是模型。

## 不做

- 不为了凑人设改数字、改状态，或把风险说成没事；
- 用户没有设定时，不自己发明角色；
- 事实段落不用 emoji，颜文字只出现在导语和收尾。
