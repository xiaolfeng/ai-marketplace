# 怎样写文案

文案从大纲来，不另起炉灶。语气只服从 [`voice.md`](./voice.md)。写完再套壳，不要在 HTML 里即兴改句子。

## 从大纲到段落

每一节按这个顺序写，写不出就回到大纲：

1. 这节要让读者带走什么（大纲里已有）。
2. 证据是哪几条，原句保留数字和对象名。
3. 按 `voice.md` 的三档写成短句：导语用用户设定的角色口吻（没有设定就用中性同事口吻），事实用正经同事。

没有证据的句子删掉。缺的进「还没钉住的」，不要用「预计」「应该」填满。

## 落盘格式

写入同目录 `copy.md`：

```markdown
# 文案

- 口吻：<用户设定的角色名，或「中性同事」>
- 标题：
- 眉题：<类型 · 时段 · 给谁>

## 导语

<完整角色口吻，两三句。第一句就要进主题，不要「现将本周工作汇报如下」。>

## 三问条（可选）

<恰好三句带走时才写：做成了 / 还卡着 / 下一步。每句是短语，不要巨大数字。没有就整段删掉。>

## 节：<和大纲相同的标题>

<正文>

## 还没钉住的

- …

## 收尾

<完整角色口吻，收在下一步。下一步是动作，不是口号。>
```

章节名必须和 `outline.md` 一致。HTML 按这里的节顺序填槽，不在套壳时改结构。套壳用 `template.html` 的 class，对照 `html-design.md` 的组件表。

## 句子

- 一句一个动作。谁做了什么、还没做什么，分开写。
- 状态用现在、已经、还没有。不要「正在持续推进中」。
- 列表前面先有一句引导。不要每条都「**加粗词。** 解释」。
- 导语可以有一处口头禅或一组颜文字；事实段落不要。

## 写完过一遍

- 有没有「本文档旨在 / 综上所述 / 值得注意的是」？
- 有没有把未确认写成已选定？
- 导语是不是角色口吻，事实是不是同事？两档反了就改。
- 拿掉标题，剩下的句子像不像作者自己在群里同步，而不是条款？
