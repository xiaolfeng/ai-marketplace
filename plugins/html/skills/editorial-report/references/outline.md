# 怎样策划大纲

大纲回答「这篇报表怎么读」，不是把材料按时间摊平。文案和 HTML 都从大纲长出来；大纲飘了，后面两步都会返工。

## 先钉四件事

写章节之前，这四项要能填。缺一就问，一次最多三个问题：

| 钉什么         | 为什么                                                         |
| -------------- | -------------------------------------------------------------- |
| 类型           | 周报、日报、月报、项目进展、复盘、指标简报、对内同步，骨架不同 |
| 读者           | 给自己留底、给组内、给负责人，密度和「下一步」写给谁都不一样   |
| 时段           | 没有时段的报表，读者不知道这是哪一周的世界                     |
| 这篇要回答什么 | 一句就够。写不出这一句，说明还在堆材料                         |

材料从哪里来：用户粘贴、当前仓的 diff / 文档、会话里已经出现过的事实。没有的标未确认，不要补剧情。

## 类型怎么长成章节

先写「读者读完要带走什么」，再给章节起名。不要先写「背景 / 进展 / 计划」再往里塞。

| 类型               | 读者通常要带走                                 | 常用章节（按需裁，不要为凑结构留空节）       |
| ------------------ | ---------------------------------------------- | -------------------------------------------- |
| 周报 / 日报 / 月报 | 这段时间做成了什么、卡住什么、下一时段先做哪件 | 做成了什么；还卡着的；下一时段先做           |
| 项目进展           | 现在走到哪、离目标差什么、谁要拍板             | 现在走到哪；差在哪；要谁拍板                 |
| 复盘               | 发生了什么、根因、下次改哪条                   | 经过；根因；下次改什么                       |
| 指标简报           | 数字相对上期变了什么、原因是否已确认           | 看哪几个数；变了什么；还没确认的原因         |
| 对内同步           | 同事读完知道自己要不要动手                     | 和你有关的变化；你不用管的边界；需要你的动作 |

章节标题用行动或问句，少用单字「背景」「总结」。一节只让读者带走一件事。

## 落盘格式

写入报告目录下的 `outline.md`（默认 `reports/<日期>-<slug>/outline.md`，用户指定了输出位置就放在最终 HTML 旁边）：

```markdown
# 大纲

- 类型：
- 读者：
- 时段：
- 要回答的问题：

## 章节

### 1. <标题>

- 带走什么：
- 证据来自：
- 还缺：

## 不写进正文的

- …
```

「不写进正文的」用来挡住：排期幻想、没有证据的完成度、读者不需要的过程流水。

## 何时停下来给用户看

- 类型、读者、时段、要回答的问题有一项是猜的。
- 章节超过四节，且说不清为什么要这么多。
- 用户没说「直接写」。

用户改了大纲，以改后的为准重写文案，不要在旧文案上打补丁。
