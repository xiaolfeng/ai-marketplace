32 · 利弊权衡与优缺点卡

TRADEOFF ANALYSIS / 方案利弊权衡 PROS VS CONS
主要优势 (Pros)
  • 吞吐量提升显著：异步化与批处理将整体吞吐量提升 3 倍以上。
  • 故障隔离彻底：单一 Worker 崩溃不影响管控面 API 响应。
  • 水平扩展灵活：计算节点可依据队列堆积长度自动弹性伸缩。
潜在代价与约束 (Cons)
  • 最终一致性延迟：写入后需轮询或监听事件获取最终状态。
  • 排障链路拉长：全链路需要统一 TraceID 贯穿日志与告警。
  • 维护复杂度增加：需额外维护分布式消息队列高可用集群。

为什么业务后端请求处理超时？

↳ 因为本次发布的新特性上线前未经过自动化 SQL 执行计划 Review。
WHY 4 · 规范

为什么没有经过自动化 SQL Review？

↳ 因为 CI 流水线中未配置自动慢 SQL 静态拦截门禁。
ROOT CAUSE · 根本原因

根本原因：发布体系缺少数据库 DDL/DML 的强制门禁检查，且熔断器超时阈值配置过长（30s）未起到快速失败保护。

57 · 常见问题解答折叠群 (FAQ)

FREQUENTLY ASKED QUESTIONS / 常见问题解答 Q&A ACCORDION
Q1 为什么旧报告的 HTML 不会自动变成新版特刊样式？

因为每份报表 HTML 均采用单文件内联交付模式，CSS 直接嵌入在产物中，确保离线双击即可完美渲染。如需将历史周报升级至新特刊视觉，需重新运行套壳脚本更新。

Q2 大纲和文案草稿放在哪里？

默认与最终 HTML 同目录，即 reports/<日期>-<slug>/ 下的 outline.md 与 copy.md，方便以后回溯与改稿。

Q3 如何指定生成最终 HTML 的输出位置？

直接在对话中向助手说明即可（例如「输出到 public/report.html」）。系统严格遵从用户声明的最终输出路径，未声明时才默认归档至 reports/。

58 · 专业术语与领域词典对照

TERMINOLOGY GLOSSARY / 领域术语对照词典 DOMAIN DEFINITIONS
SLO (Service Level Objective)
服务等级目标。SRE 团队设定的核心稳定性指标（如可用性达到 99.95%），用于衡量服务是否健康。
ADR (Architecture Decision Record)
架构决策记录。用于捕获重大架构决策、选型背景、权衡及长期约束的可审计文档。
CAPA (Corrective and Preventive Actions)
纠正与预防措施。故障复盘后设立的防再发整改项列表，明确责任人与验收上线周期。
